# 三态决策检查器离线修复与最小后续验证

## 修复范围

`minimal_validation.py`的检查器更新为`market-rework-decisions/2`。只修改验证驱动与测试，不修改原生权限、资料来源、执行、审批和交付契约。

旧实现用子串搜索拒绝/允许词，既误拒“不读取”，也可能把“不能拒绝读取”误当拒绝。现在对每一行的完整读取决定做有限语法检查：拒绝行支持“不读取、不访问、不检索、不进入执行快照”及既有拒绝表达；并列子句必须逐项拒绝。允许行接受已知范围表达，并要求决策与原因中同时出现接收部门、版本及授权范围。原因不能夹带额外许可或已知绕过说明。

拒绝否定反转、允许/拒绝混杂、先读取后补共享、紧急例外、仅批准就可访问、撤权后继续使用等已知表达。状态名称按限定集合匹配；重复状态、缺少原因及额外列均拒绝，不能靠另一条安全行掩盖问题。未知或含糊表达仍失败并留给人工核对；这不是通用中文语义证明，也不授予资料访问权。原来的交接清单检查仍保留，不能用这些文案检查替代宿主来源事实检查。

回归分为：同义表达正例、反转/混合表达、条件越权、共享范围绕过、畸形/重复表、历史正文只读重现，以及原生返工/审批/来源回归。完整假传输链采用本次真实失败的同义表达，仍须经过原队列、工具、独立校验、旧版批准拒绝、新版批准和本地ZIP；另有完整链反例证明否定反转在批准前停止。

历史原响应、候选、停止报告和证据ZIP只读核对SHA，不改写、不改成通过。新结果单列于`reports/rework-decision-checker-offline-20261017.json`。旧活动仍为5次用尽、审核未完成；本轮真实模型调用0次，不读取密钥或旧预算。

## 完成新版审核与本地交付的最小方案

**优先方案是新增模型请求0次，模型预算0元。** 已有市场v2及5个工具回执，无需为模型无关的审核和打包重新生成正文。该后续闭环尚未执行，不能把本次离线修复写成完成交付。

1. 从已停止的隔离案例创建全新的本机验证副本：只读SQLite backup并复制必要虚构资料/签名状态，保留原库、原台账和原报告。只复制必要文件，不读取或复制旧预算、不重新授权任何Campaign。记录来源文件及候选摘要、新目录和新报告路径；目录已存在则拒绝执行。
2. 新应用只开离线审核/交付路径，不启动Worker，不挂载真实Campaign。将所有模型端口、网络传输、密钥读取及预算读取设为失败；不得以离线生成替代原市场v2。预检没有活动运行/租约，资料引用在新副本仍能定位，原正文、候选摘要和执行源码版本保持一致。任何必要前提无法保留即停止，不手改来源清单或摘要凑通过。
3. 通过原本机身份服务为合成测试审核账号建立新会话；必要的恢复仅作用于新副本内该测试账号，不触碰用户账号、不注入管理员principal、不直写审批记录。无法合法取得审核权限即停止。
4. 对原市场v2运行修复后的三态检查、原生当前共享检查、实际引用/来源/工具回执复核，逐段核对返工意见；检查不通过就留存新失败。尝试以市场v1摘要/版本批准必须409；原v1/v2产物字节不变。
