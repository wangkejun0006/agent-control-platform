# 返工结构、来源与正文契约：离线修复

本轮不调用真实模型、不读取供应商密钥、不修改原仓库、不推送或公开。历史活动保持20、22、21次且关闭；旧响应、原报告、候选和审核记录按哈希核对，不改写为新规则下的成功结果。

## 修复方式

| 问题 | 实际改动 | 拒绝路径 |
|---|---|---|
| 返工时模型改错任务包类型、增加章节 | 新增`delivery-package-prose/2`。模型只填写固定`section_id`的摘要和风险文本；宿主从原生模板组装类型、章节名称、顺序、数量，仍执行原校验与审批 | 旧式`type/candidate`、额外槽位、重复、乱序、缺失或类型错误全部拒绝；不清洗错误响应冒充成功 |
| 本部门资料与上游产物混淆 | 原始资料使用`department_authorization`；交接产物使用`approved_explicit_handoff`，附来源部门、候选摘要与版本。依据实际记录而非文件名 | 正文来源标签必须与相应证据匹配；禁止模型自行编写文件名。真实文件、版本、行和授权依据由宿主展示；共享产物必须被实际引用 |
| 运维恢复过程混入业务设计 | 分开保存`business_feedback`与`recovery_notes`。失败恢复原因保留在事件/尝试中，不传给规划或专业模型作为业务要求；上游变化单列依赖事件 | 恢复入口仍校验状态、负责人权限和不确定操作确认。已知恢复文案、假称跳过实际重跑的检查会被正文门禁拒绝 |
| 删除副本、零幻觉、生产可用等无依据承诺 | 新增`delivery-content/1`，在模型提案、工具最终结果和人工审核入口重算；结合实际来源清单与工具回执 | 已知的错误承诺不能靠附上规范文字蒙混过关；旧`PASS`和伪造来源标签也不能绕过重新检查 |

规划表格与正文表格是两个对象：负责人要求增加“三态决策表”和“交接验收清单”时，模型在已有任务包摘要内规划，在最终交付正文中增加对应小节，不增加原生任务包章节或自行填写批准字段。

旧资料不原地迁移、不补写新版本标记。旧候选只读保留，新审核会检查当前正文规则和宿主来源绑定；不满足时必须新建修订。停用后停止后续使用与保存历史审计证据分开表述，不能承诺未实现的删除。

## 验证范围

- 结构：固定身份与章节由宿主生成，恶意槽位、旧失败结构、文本/风险类型及顺序错误均被拒绝。
- 来源：伪装成`approved-`的本部门文件仍是本部门资料；来源标签调换、杜撰文件、漏引用实际共享产物、正文引用未选索引均被拒绝。
- 正文：历史Q2来源混淆、Q3恢复污染和检查执行矛盾、Q4删除承诺作为反例；反向验证“不承诺”“不删除历史证据”等安全表述。
- 审核：即便预存`checks_passed=true`，篡改正文或来源清单仍不能批准；原候选和旧审核保持不变。
- 恢复：注入规划失败后，通过合法恢复创建新尝试；记录中保留恢复原因，但问题、任务包和交付正文不含恢复说明。
- 闭环：在新临时数据库以离线产物准备上游、形成并退回市场第一版；用5次假传输请求完成市场新版规划、实际5项工具、新版审核与ZIP交付，旧版批准被拒绝，旧候选不改写。

自动化测试账号的决定只是本机测试，不表示用户真人审核。假传输的5次是协议与流程验证，不是真实模型表现或费用。具体测试结果和旧文件哈希核对见`reports/offline-rework-validation-20261017.json`。

## 完成返工审核闭环的最小真实验证方案（待授权）

**计划并硬限制5次请求，费用预留0.30元，无自动重试。** 所有付费入口共用新Campaign，不恢复旧21次活动，也不沿用其剩余3次。输入上限8000、输出上限2048，按代码内固定的输入3元/百万、输出12元/百万预留，每次最高0.048576元，5次最高0.242880元；这不是供应商实扣报价。

前置步骤不使用模型：新建独立状态库；用明确标记的离线执行器生成产品和技术产物、审批并显式共享；生成市场第一版并以测试账号退回，填写三态表和验收清单要求。资料全为虚构，先离线确认当前内容门禁通过。这样只验证“市场返工→审核→本地交付”，不声称本轮三个部门均重新调用真实模型，也不把旧活动未完成的记录改为完成。

| 请求 | 动作 | 必须验证 |
|---|---|---|
| 1 | 市场返工澄清 | 原问题/选项身份与推荐标记保留，恢复信息不进入业务问题 |
| 2 | 市场任务包文案 | 固定槽位由宿主组装成原生任务包，原章节不增减，表格要求进入摘要；负责人确认计划 |
| 3 | 查询、检索的工具意图 | 两个真实工具执行；接收部门只能看到自己的资料及显式交接产物 |
| 4 | 校验、验收的工具意图 | 两个真实检查执行并留回执，声明以本次实际结果为准 |
| 5 | 最终候选意图 | 第五项工具实际提交候选；三态决定和清单实质修订，来源与引用匹配，不写恢复过程或删除承诺 |

之后不再调用模型：核对正文与v1差异、三态表每行的决定及原因、接收部门/版本/范围/撤权检查；测试旧摘要或旧版本批准返回拒绝；测试账号批准新版，再生成仅供本地下载的ZIP。执行记录、工具回执、来源索引、审核与费用保存在独立新报告。

失败响应仍计数和留档，合同、来源、正文或预算任何一项失败就停止，不能为凑闭环修改模型原文或放宽门禁。若一次失败导致剩余额度不足，不重开活动；另报修复与验证预算。此方案尚未获得执行授权，本轮真实请求为0。

## 能力边界

来源类型和结构身份有确定性宿主约束；自由正文仍使用有限中文规则与实际证据检查，不是通用自然语言语义证明。规则可能拒绝需要人工解释的表达，也不能发现所有隐含承诺。后续真实小样本仍须逐段核对，不能把离线成功写成模型已验证、真人批准或生产可用。
