# 演示脚本与面试讲解

## 一条可以复现的流程

1. 启动 README 中的本地服务，进入“离线执行演示”，确认虚构资料、零模型调用与脚本审批标识。
2. 点击“运行离线演示”。服务运行固定场景并保存新状态目录，不使用原业务数据库或真实凭据。
3. 打开成功场景的回执：资料包含三个集合与九条虚构记录，独立预期结果校验通过后，原 CompanyEvaluator 再核对 Task / Result / Audit。
4. 查看成功任务的 Worker 租约闭合，再查看运行中取消场景：Operator Grant 与控制事件进入台账，进程被终止，租约变成 `cancelled`。
5. 查看质量错误和重复 JSON 场景：HTTP 成功或进程退出正常都不能替代契约与质量通过。
6. 查看幂等重放：同一任务读回台账，Worker 启动数为零。中断的不确定尝试不会自动执行第二次。
7. 查看生命周期与 Tool 组合：评估通过仍需要脚本审批夹具；三个 Tool 被精确绑定到组合，未批准的操作被拒绝。此处没有真实发布。
8. 切换原“公司治理总览”“Model Routes”“Task Scope 审计”“Evidence & Audit”，展示保留的审批、撤销、作用域核对和服务端写后读回。

## 能据实讲出的能力

- 能把 Agent 的规划/建议与确定性执行权限分开，避免“模型说能做”直接变成执行授权。
- 能设计并验证进程边界、结构化契约、明确失败原因、不可变结果引用、独立评估与可重放证据。
- 能处理取消、超时、输出超限、重复提交、不确定执行结果，以及权限/版本变化。
- 能区分 Agent 与 Tool 生命周期，按精确 release、Policy、Grant、数据 revision 和预算组成运行环境。
- 能保留并迁移已有服务、工具包、迁移脚本和前端，说明哪些行为被实际验证，哪些还依赖外部系统。

不要把当前确定性资料执行器说成真实 LLM 自主 Agent，也不要把脚本审核说成真实用户审批。模型效果、Postgres 集成、OS 隔离和跨机器运行都需要单独证据。
