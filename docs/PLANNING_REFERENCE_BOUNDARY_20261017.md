# 规划与执行的证据引用边界：离线修复

本轮真实模型调用0次，不读取供应商密钥，不改写旧活动、旧响应、旧报告，不修改原仓库、推送或公开。

## 已实现

规划不再复用执行正文提示。`PLANNING_PROMPT`用于澄清问题与任务包文案，明确当前没有检索证据，仅可描述未来如何取证、区分来源、核对授权、版本与行号。它不含具体数字索引示例，也不提供实际证据清单；请求上下文增加`evidence_state=not_retrieved`和`reference_mode=planning_policy_only`。

执行使用独立`EXECUTION_PROMPT`，只允许使用本次实际检索结果中的证据索引。原来的“本部门资料配某个固定数字、交接产物配另一个固定数字”示例已移除；资料类型仍由宿主记录决定，不能由文件名或模型自行指定。

新增`delivery-planning-references/1`及独立`planning_reference_boundary`门禁，覆盖问题标签、选项说明、各摘要和风险说明。即使调用者意外提供了资料列表，规划仍不能生成数字引用、具体证据编号、资料链接或具体行号。含引用的目标或返工意见保留为不可信输入，不能成为输出引用的授权。

任务包固定结构仍由宿主组装。规划拒绝时保留模型原文，不删除索引、不把错误响应转换成成功。新的规划规则版本进入请求幂等摘要，不能把旧响应当作新规则下的结果。

执行、工具提交、独立结果校验和审核入口的来源绑定保持不变：正文索引必须存在且被实际选用；来源类型、共享产物、目标部门、版本、候选摘要与原始记录匹配；预存的PASS和伪造来源清单不能绕过重新检查。没有关闭或跳过规划来源检查，也没有放宽执行或审核门禁。

通用提示中的“不承诺”表述拆为逐项否定，避免长句照抄后被既有有限规则误判；既有执行/审核承诺检查没有因此放宽。

- 三个部门、澄清和任务包两个阶段的实际请求均检查：系统提示无具体引用示例、没有执行正文提示，且声明尚未检索。
- 模拟模型复述一般取证规则可以通过；向问题、摘要或风险说明注入索引会拒绝。
- 覆盖普通、空格、全角、范围、多索引、编号、链接及具体行号；不能通过为规划传入伪造证据来放行。
- 只读重现上轮真实响应：槽位结构依然有效，但新增明确的规划边界检查仍拒绝；原文件SHA保持不变。
