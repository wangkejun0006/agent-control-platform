# Orbit Agent Control Platform

基于既有项目实现的独立脱敏展示版本：部门规划、确定性任务路由、签名授权、受控进程执行、独立评估、可重放台账、Worker 租约、Agent/Tool 生命周期、不可变运行时组合，以及完整本机交付工作台。

默认首页现为**任务工作台**，主案例为虚构“团队知识助手”功能交付。产品、技术、市场三个部门依次完成规划、执行、交接和审核；计划确认、产物审核与最终本地交付分别由登录用户操作。原治理控制台、库存演示和历史真实模型报告保留在独立导航区。

默认运行 **本机离线演示**。主案例为虚构团队知识助手，原文具目录、工单和发货资料作为回归示例保留。经明确授权的原真实验证见 `reports/live-validation.json`；2026-10-17跨部门工作台验证见 `reports/workbench-live-validation.json`，两项活动均已关闭，查看证据不会调用模型。工作台支持登录用户人工审核，本次自动化验证使用本机测试账号，不声称用户已亲自审核，也不代表企业身份认证或生产授权。

此前跨部门验证使用22次真实请求，保守估算0.109965元，包含8次规划、12次工具对话、2次越权/自批拒绝探针；产生20个实际工具回执，完成两次部门交接、市场v1退回/v2修订及本地ZIP。**流程契约通过，正文仍需人工复核**：市场文案把部门隔离过度概括，未清楚保留“已批准产物可显式共享”的例外。原文、质量问题和闭环证据均保留；详见 [验证说明](../WORKBENCH_LIVE_VALIDATION.md)。管理员可在“示例与验证”查看该历史活动的只读汇总、返工前后原文并下载其本机验证交付包。

随后的离线修复统一了规划/正文提示词、默认文案与独立语义门禁：**未经共享的资料不能访问；已批准并显式共享的产物可按接收部门、绑定版本和授权范围交接使用。批准本身不等于共享。** FAQ发布为v2，旧版保留；旧真实响应和ZIP未改写。历史市场v2在新门禁下会被拒绝，该次离线修复新增模型请求0次。检查仅覆盖明确的中文规则与已知矛盾，不认证全部自然语言语义。离线整理示例见 [访问与交接说明](../examples/sharing-corrected-market.md)。

**最新共享边界真实验证已关闭，最终返工交付未完成。** 本轮独立预算21/24次、保守记账0.122883元/2元：三个共享状态判断正确，两个实际交接和下游引用通过，产生15个工具回执。但两次规划响应违反结构契约；一次显式修复后继续，市场返工任务包再次被拒绝，剩余3次不足以完成4次必要调用，因此停止。没有市场第二版候选或最终交付ZIP；仅有明确标注的证据包。参见 [本轮完整说明](../SHARING_LIVE_VALIDATION_20261017.md) 和 `reports/sharing-live-outcome-20261017.json`。新旧台账、停止报告、原始响应均独立保留；正文另有来源归属和未经验证的保留承诺问题，仍需人工复核。

在 WSL/Linux 的项目根目录执行。首次安装依赖需要包仓库网络；后续演示无需外网、模型、Docker、原私有仓库或凭据。

```bash
uv sync --locked --extra loopback-d0
npm ci --prefix packages/agent-authoring-toolkit --ignore-scripts
npm ci --prefix packages/orbit-control-plane-console --ignore-scripts
npm run build --prefix packages/orbit-control-plane-console
bash scripts/run_demo.sh
```

打开 http://127.0.0.1:8432 。只监听本机：

1. 首次创建本机管理员账号，口令至少12位；后续部门账号须管理员或本部门负责人审批。本机Cookie会话不是企业OIDC身份。
2. 在“Agent与工具”中评价内置候选，然后明确批准激活；支持批量评价和绑定精确发布摘要的批量批准。登记、评价、激活均不直接签发任务执行授权。
3. 创建交付任务，在“资料”中显式导入13份虚构资料并授权三部门使用，也可上传本部门UTF-8文本、Markdown、CSV或JSON。旧版保留，同版本冲突不自动选一个通过。
4. 在产品部门“规划”回答问题卡、填写计划审核说明并确认，再提交受控执行；在“产物与审核”核对检查、引用和正文，批准并授权交接技术部门。技术与市场部门按相同流程完成各自任务。
5. 三部门当前产物全部获批准后，在“概览”填写最终审核说明，生成可下载的本地ZIP交付包。退回修改会保留旧候选和意见，并使受影响下游版本失效。

“示例与验证”保留原来的固定离线演示和历史模型报告；“治理与审计”保留原模型路线审批、Task Scope核对、证据及移动只读视图，并使用当前本机账号权限。

一个启动命令同时启动Web和单Worker；工作台使用独立的 `.runtime/workbench/`，不覆盖原演示数据库或已关闭Campaign。停止Web会关闭其Worker；异常中断的运行保留 `runtime_interrupted_unknown`，必须核查并明确创建新尝试，不能删除台账重试。`ORBIT_WORKBENCH_STATE_ROOT` 可显式指定本项目 `.runtime/workbench/` 内或系统临时目录中的专属私有绝对目录；其他位置拒绝，不接受浏览器传入物理目录。

也可以直接运行 CLI，每次使用新的状态目录保留证据：

```bash
PYTHONPATH=src:. uv run --locked --offline python -m showcase.demo \
  --state-root .runtime/my-first-demo --report reports/offline-demo.json
```

复用同一目录会重放已有结果；不重新运行 Worker。中断后若只剩未闭合租约，执行会拒绝自动重试并要求核查。不要删除台账来伪装重试成功。

## 演示内容

- 读取虚构资料，经原 Router 调用受限 Python 子进程；按独立编写的预期结果检查资料产物，再经原 CompanyEvaluator 核对 Task、Result 与 Audit 引用。
- 在原追加式哈希链台账中记录任务、Worker 租约、结果、评估与租约闭合；重放不会重复执行。
- 故障注入覆盖质量错误、任务引用漂移、重复 JSON 键、输出超限、超时、运行中取消、无效授权、未注册能力与非演示数据分类。
- 通过原 Agent Lifecycle 验证“评估不替代审批”；通过原 Tool Lifecycle 登记、评价并以脚本审批夹具激活三个工具契约。
- 通过原 RuntimeComposer 固定 Agent、Tool、模型路线夹具、Policy、Grant、输入 revision 与预算，并拒绝未批准的 Tool 操作。此部分验证组合，不执行真实下载或发布。

离线资料处理是确定性执行器；真实模型能力单独记录，不能将离线测试冒充模型验证，也不声称已验证多 Agent 自主协作。新增真实验证仍需另报请求次数与费用预算。

## 已完成的限额真实验证

2026-10-16：用户授权最多 24 次请求、费用预留 2 元；实际台账 20 次，其中 19 次获得有效响应、1 次连接超时。已知用量按峰值输入 2 元/百万 token、输出 8 元/百万 token 保守估算为 0.072556 元；超时请求继续保留 0.032384 元最高预留，合计 0.104940 元。这不是账单实扣金额。授权已关闭，剩余 4 次不可自动沿用。

- 原生 `DepartmentCockpitService`、LangGraph SQLite checkpoint 完成澄清、任务包生成和精确摘要审批；规划路线明确绑定真实模型，不沿用原夹具的供应商标签。
- 原 Tool Registry 严格导入三个独立本地契约，经 Tool Lifecycle 和 RuntimeComposer 验证后，通过原 BoundedProcessRunner 实际执行查询、统计和本地候选提交。工具进程不继承密钥环境，也不拥有任意路径、代码或发布接口。
- 两条业务任务、一次返工生成三个候选，产生 9 条实际工具进程回执。指标固定核验为缺货 `PO-102`、未结工单 2、发货单位 8。候选必须有查询与统计回执和证据 ID，审核绑定版本及摘要，旧版本不能再次批准。
- 预算在取密钥和网络请求前持久预留；失败、超时、协议修复均计数，没有 SDK 自动重试。规划、原生工具对话、对抗验证共用同一入口。三个遗留付费直连传输已关闭；注入的离线测试传输仍保留。
- 两条真实对抗提示均明确拒绝发布、泄露密钥和自我审批。真实响应中的只读调用最初也因额外 `index` 元数据被拒绝；统一规范化后以保存响应离线重放通过，新增模型请求为零。所有初始失败保留，不能把重放说成新的真实模型成功。

默认 CLI 和 UI 仍离线。`python -m showcase.live_flow report` 只重建报告；`run` 不会覆盖已有台账。`resume` 仅允许未耗尽的、可修复的同一活动继续，拒绝已完成、用量未确认或预算耗尽的活动。新活动必须有新的人类预算授权，不能删除台账绕过。

密钥仅在获授权的传输进程中选择性读取用户目录中的既有 Hermes 配置，不写入源码、数据库、请求快照或日志。真实网络走显式本机代理，保留 TLS 验证、禁止重定向、单请求 90 秒总时限；这些是本机环境条件，不是可移植部署配置。

这次历史真实活动的边界仍保留：审核是脚本夹具；首版库存摘要出现资料未给出的补货阈值推断，修订稿删除该推断并补充证据限制。该历史活动使用独立Campaign，并未被改写成新工作台的登录审核记录。

新工作台已接入原SQL队列、签名Grant和租约，并改为本机账号点击审核；**新案例仍是离线规划和确定性专业决策端口，不能当作新一轮真实LLM推理证据**。受控工具确实执行资料检索、版本/权限/引用检查和本地候选提交；正文为受控模板与实际证据组合，检查通过不认证全部语义。统一模型入口没有启用付费模式，旧活动的剩余额度不会沿用。

## 保留范围与边界

源码、测试、数据库迁移、工具包和控制台来自固定版本的原实现；改造没有导入原 Git 历史。原仓库不作为运行时依赖。组织标识、模型配置、审核身份和主题资料已替换；契约摘要为脱敏副本重新冻结，不冒充原组织发布或原批准证据。

原 Postgres/Outbox、OIDC、mTLS、签名授权、队列和运行时制品代码继续保留；新工作台使用SQLite单Worker、原生签名验证、独立进程和本机账号。未验收生产部署、真实身份提供方、容器隔离或跨机器运行。进程、环境和离线网络限制不等于OS级沙箱。Hermes/Codex仍为候选；本轮只管理固定演示发布的生命周期，不提供任意新版本、任意工具或可视化拖拽工作流编辑器。暂停后的固定候选不通过伪造批准一键恢复。

详见 [功能对应表](../FEATURE_PARITY.md)、[演示说明](../DEMO.md)、[验证报告](../../reports/VALIDATION.md)。`.runtime/` 为本机私有运行、来源对照与失败证据，不能纳入公开材料。本目录尚未独立建立 Git 历史，未提交、推送或公开。
