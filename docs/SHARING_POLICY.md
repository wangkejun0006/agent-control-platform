# 访问与交接文案的离线修复

本次规则：未经共享的资料不能访问、读取或检索；已批准并显式共享的产物可以交接使用，但仅限指定接收部门、绑定版本与授权范围。批准不等于共享，交接也不授予读取来源部门其他资料的权限。撤权或版本失效后停止使用。

## 改动

- `sharing_policy.py` 统一中文规则、提示词约束和有界语义检查；规则版本为 `delivery-sharing/1`。
- 规划提示与候选提示都包含共享例外；规划与正文提案在结构校验后检查语义。默认离线产物也明确写出三种状态：未共享拒绝、仅批准未共享拒绝、批准且显式共享的指定版本允许。
- 独立服务端从作者正文重新计算检查，不信任执行器的PASS。受检内容须与实际产物的作者段落及规则版本绑定，引用原文和用户输入不能伪装成访问授权。
- 新批准、交接、下游规划和最终交付都重新检查当前规则。旧候选不具备当前检查时显示返工提示；旧正文、摘要、批准及已形成的交付记录不回填、不篡改。
- FAQ新增v2，当前13份资料清单选择新版；v1原文件保留。已有任务的资料快照不自动替换。
- 任务页将“默认拒绝”和“有条件交接”并排展示，详情可展开规则；历史原文可收起并独立滚动，移动端无横向溢出。历史报告显示离线修复状态，不冒充新真实模型结果。

## 验证

核心修复便携集399项运行、391项通过、8项可选跳过、0失败/错误，407.35秒；旧数据操作门禁收尾后32项定向回归全部通过，覆盖原有16项工作台测试及新规则/协议用例。前端lint/类型、3项单元/构建及最终6条浏览器用例通过。不同范围有重叠，不累加为独立测试总数。

负向用例包括：绝对禁止所有跨部门资料、批准后读取全部资料、追加正确规则掩盖矛盾、缺少绑定版本、执行器伪造PASS，以及旧通过记录继续批准/交接。正向用例通过原生审批与交接接口证明，仅批准时下游拒绝，明确共享获批版本后才允许规划。

历史市场v2在新检查下被拒绝；离线整理示例为 `examples/sharing-corrected-market.md`，不是真实模型重新生成的响应。原22次活动、前一20次活动均关闭，61个历史私有证据文件摘要未变，原真实汇总JSON与修复前检查点一致。本轮模型调用0，不读取模型密钥，未修改原仓库、推送或公开。

初始回归发现“版本失效”关键词不能代替“绑定版本”，已收紧规则并保留首次失败日志。框架弃用与原生fork警告保留，不作为失败隐藏。

## 边界

这是针对明确中文表述和已知矛盾的规则检查，不是通用NLI、任意措辞下的完备逻辑证明或全文事实认证。未来模型输出仍需人工复核，新的真实验证必须另获授权。原生权限、批准版本与共享记录始终是实际访问依据。
