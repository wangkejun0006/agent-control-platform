# 原功能对应与本轮边界

## 共享语义离线修复（2026-10-17）

新 `sharing_policy.py` 定义版本化规则与有界中文语义检查。未共享资料拒绝；已批准且显式共享的产物只向指定接收部门、绑定版本和授权范围开放；批准不自动共享。规划/候选提示词和离线正文使用同一规则。真实适配端口在结构校验后检查规划与候选；服务端独立重算正文检查，伪造PASS不能批准。引用原文与返工输入不作为作者权限声明来检查。

FAQ v2与显式允许/拒绝案例补齐，旧FAQ、旧真实响应和旧ZIP保留。管理员历史页展示当前离线修复状态，不将其冒充重新通过真实模型验证；任务页提供并排访问边界与可折叠交接说明，桌面/移动端验证。

本轮不读取模型密钥、不调用模型、不恢复任何Campaign。语义门禁是限定中文表达与已知矛盾的规则检查，不等于通用NLI或全文事实认证；原生授权、版本和交接记录仍是访问依据。

## 真实工作台适配增补（2026-10-17）

在保留默认离线模式的前提下，新增显式Campaign规划适配、模型工具意图桥接、真实候选正文与私有IPC请求组件。原预算网关是唯一付费预留入口；Worker和工具子进程仍无凭据环境且禁止外网。规划沿用原问题卡、任务包、LangGraph中断和确认；专业执行沿用原Router、组合、签名Grant、SQL队列、租约及独立评价。

市场部门此前在catalog-backed原入口有固定rollout限制。仅显式工作台适配将其纳入既有市场问题/章节契约；原入口默认仍限制产品/技术部门。三部门路线使用原兼容性校验允许的备用路线结构，没有关闭兼容、权限或审批门禁。Hermes/Codex仍未接入。

真实结果为22次请求、20个实际工具回执、两次交接、市场返工和本地交付；审批由自动化本机测试账号操作，不冒充真人。活动关闭后不使用余下2次额度；旧20次活动保持关闭。正文发现隔离措辞未明确共享例外，故只能称流程契约验证通过，不能称内容全面正确。详见 `WORKBENCH_LIVE_VALIDATION.md`。

下方2026-10-16部分记录的是整合首轮离线验收状态；本节为后续增补，不把新能力追溯归为原项目或实习成果。

## 有意保留的复杂度

Task、RouteDecision、Result、Evaluation、Control、Lease 和 Audit 仍是独立对象。审批、评估、健康状态、可执行范围与发布授权仍分离。两个生命周期台账没有合并，Tool 也没有被改成 Agent 的隐式权限。

新增适配只把演示执行依赖替换成项目内虚构资料。它不代表原 Scientific 进程集成、原部署或真实模型规划已经验收。

## 实现差异

1. 包名、组织和角色标识替换为 Orbit / 虚构组织，示例 Provider 地址改为不可解析的 `.invalid` 域名；原审批者改成 DEMO，历史审批文字改成脚本夹具。
2. 原契约检查保持启用；脱敏内容对应的摘要在准备步骤中显式重建，运行时不自动刷新。原发布 commit/tag 字段只作为冻结契约格式兼容元数据，不是这些改造字节的真实 Git 身份。
3. 台账增加一个严格限定的来源摘要表示：只有 `frozen_offline_python_worker` 和 `orbit.offline-receipt/1` 允许完整 `sha256:` 来源；原跨仓 Git Adapter 仍要求原 Git 校验。租约与结果来源必须精确一致。
4. 本地适配新增固定资料的独立预期结果校验、执行互斥、重复执行重放与中断后拒绝盲目重试。
5. 原 Key 验证测试的辅助断言曾依赖哈希字典的首条顺序；虚构模型改名后暴露了偶然依赖。现在检查恰有一个当前预留，并明确断言每次无效响应留存 `test_failed`，不改变实际 Key 验证逻辑。
6. 修复原持久队列的取消竞态：领取任务后、子进程启动前收到取消，现在也写入 `runtime_cancelled`，与运行中取消保持一致。新增测试固定触发该窗口，断言不会调用 Handler，并保留取消原因。
